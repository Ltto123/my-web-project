## 一、FastAPI 框架核心

### 1. FastAPI 应用创建与生命周期

**概念/原理**：FastAPI 是一个基于 ASGI（异步服务器网关接口）的现代 Python Web 框架，底层依赖 Starlette（Web 核心）和 Pydantic（数据校验）。创建 `FastAPI()` 实例就是创建了一个 ASGI 应用对象，它作为一个请求调度中心，接收 HTTP 请求、匹配路由、调用处理函数、返回响应。

**项目中的用法**：在 `backend/main.py` 中：

```python
app = FastAPI(title="Blog System API")
```

启动时用 uvicorn（ASGI 服务器）来拉起它：
```dockerfile
CMD ["uvicorn", "backend.main:app", "--host", "0.0.0.0", "--port", "8000"]
```

`backend.main:app` 就是告诉 uvicorn："去 backend/main.py 里找那个叫 `app` 的 FastAPI 实例，用 ASGI 协议跑起来。"

**生命周期关键节点**：
1. **应用启动时**：所有顶层代码执行一次（import、`Base.metadata.create_all()` 建表、`_ensure_posts_created_at_column()` 迁移）
2. **每个请求到达时**：FastAPI 匹配路由 → 解析参数 → 调用依赖注入 → 执行路由函数 → 返回响应
3. **应用关闭时**：FastAPI 自动清理连接池等资源

### 2. 路由定义

| 路由 | 方法 | 功能 |
|------|------|------|
| `/api/v1/posts` | GET | 获取文章列表 |
| `/api/v1/posts` | POST | 创建文章 |
| `/api/v1/posts/{post_id}` | GET | 获取文章详情 |
| `/api/v1/posts/{post_id}` | DELETE | 删除文章 |
| `/api/v1/posts/{post_id}/like` | POST | 点赞/取消点赞 |
| `/api/v1/posts/{post_id}/comments` | GET | 获取评论列表 |
| `/api/v1/posts/{post_id}/comments` | POST | 创建评论 |

URL 设计遵循 RESTful 规范：资源名用名词复数，子资源用嵌套路径。

### 3. 路径参数、查询参数、请求体

- **路径参数**：`/posts/5` 中的 `5`，用于标识资源
- **查询参数**：`?search=中药`，用于过滤/搜索/排序
- **请求体**：POST/PUT 请求中 body 里的 JSON 数据

### 7. 依赖注入（Depends）

```python
def get_db():
    db: Session = SessionLocal()
    try:
        yield db        # 把 db 交给路由函数
    finally:
        db.close()      # 请求结束后自动关闭连接
```

## 二、数据库与 ORM（SQLAlchemy）

### 1. Engine 和 Session

| 概念 | 作用 |
|------|------|
| **Engine** | 维护数据库连接池，全局一个就够了 |
| **Session** | 一次与数据库的"对话"，每次 HTTP 请求应该开一个新的 |
| **SessionLocal** | 工厂函数，每调用一次就生产一个新的 Session 实例 |

```python
engine = create_engine(SQLALCHEMY_DATABASE_URL, connect_args={"check_same_thread": False})
SessionLocal = sessionmaker(autocommit=False, autoflush=False, bind=engine)
```

### 2. 声明式模型定义

```python
class UserModel(Base):
    __tablename__ = "users"
    id = Column(Integer, primary_key=True, index=True)
    username = Column(String(50), unique=True, nullable=False, index=True)
    email = Column(String(100), unique=True, nullable=False, index=True)
    password_hash = Column(String(255), nullable=False)
```

### 3. 外键和约束设计

```python
class LikeModel(Base):
    post_id = Column(Integer, ForeignKey("posts.id", ondelete="CASCADE"), nullable=False)
    user_id = Column(Integer, ForeignKey("users.id", ondelete="CASCADE"), nullable=False)

### 4. CRUD 操作模式

```
构造对象 → db.add() → db.commit() → db.refresh()

### 5. SQLite vs PostgreSQL

| 维度 | SQLite | PostgreSQL |
|------|--------|------------|
| 部署模式 | 嵌入式，单文件 | 独立服务器进程 |
| 并发能力 | 读写串行 | 真正的多用户并发，MVCC |
| 适用场景 | 个人博客、原型 | 多用户 Web 应用 |

def create_access_token(user_id: int) -> str:
    expire = datetime.now(timezone.utc) + timedelta(hours=24)
    payload = {"sub": str(user_id), "exp": expire}
    return jwt.encode(payload, SECRET_KEY, algorithm=ALGORITHM)

## 八、架构总结

### 完整请求链路

```
浏览器访问 → FastAPI FileResponse(HTML)
→ 浏览器加载 JS → fetch API 请求
→ FastAPI 路由匹配 → Depends(get_db) 创建会话
→ Depends(get_current_user) 解析 JWT
→ SQLAlchemy query → SQLite 执行 SQL
→ 序列化 dict → JSON Response
→ 前端 result.data → 动态渲染 DOM
```

### 优点

- 全栈自洽：后端 FastAPI + 前端原生 JS + AI PyTorch + Docker
- 懒加载：AI 模型首次请求时才加载
- 可选鉴权：未登录可浏览，登录后可互动
- 统一响应格式：`{code, msg, data}`
- 部署友好：一条龙自动化

### 可改进之处

- JS 文件有大量重复代码 → 提取公共模块
- `innerHTML` 渲染有 XSS 风险
- Token 存 localStorage 易受 XSS 攻击
- deploy.py 含明文密码 → 应用环境变量

### 扩展路线

```
第一阶段（当前）：个人博客，SQLite，单容器
第二阶段（增长）：PostgreSQL + Redis缓存 + 模块化前端
第三阶段（扩展）：CI/CD + 审核过滤 + 图片压缩
```
